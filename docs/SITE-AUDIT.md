## 1. Кибербезопасность и защита данных

### 1.1. SSL/TLS
| Проверка | Результат |
|----------|-----------|
| Прод `northmp.su` | HTTPS отвечает (DDoS-Guard), но **контент приложения — 404** |
| Туннели/локально | TLS зависит от прокси (loca.lt / cloudflare); приложение само по HTTP |
| TLS 1.2/1.3 | На edge-прокси обычно поддерживаются; **HSTS на приложении** добавлен при `https` / `x-forwarded-proto` |

**Рекомендация:** выкатить это приложение за reverse-proxy с валидным сертификатом на `northmp.su`, включить только TLS 1.2+ и HSTS на уровне nginx/Caddy.

### 1.2. OWASP Top 10 (по коду)
| Риск | Статус | Комментарий |
|------|--------|-------------|
| **A01 Broken Access / sensitive data exposure** | **Было критично** | `express.static(ROOT)` отдавал `/server/data/shop-orders.json` (телефоны, email, имена заказов), `cms.json`, исходники. **Исправлено:** блок `/server`, `.env`, `package.json`, `node_modules`, `*.md`. |
| SQL Injection | Низкий | Нет SQL; JSON-файлы |
| XSS | Средний | CMS HTML санитизируется (`server/rich-html.js`); на клиенте много `innerHTML` — риск при компрометации CMS/админки |
| CSRF | Средний/низкий | Admin — Bearer token (не cookie); публичные POST без CSRF-токена |
| Malicious upload | Контроль | multer + image mimetype; нужна проверка magic bytes на проде |
| SSRF | Контроль CDEK/YooKassa URL из env | Не принимать произвольные URL от клиента |

### 1.3. Security Headers
**До аудита:** отсутствовали (только `X-Powered-By: Express`, `Access-Control-Allow-Origin: *`).

**После фикса в этом PR:**
- `Content-Security-Policy` (baseline)
- `X-Frame-Options: SAMEORIGIN`
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy`, `Permissions-Policy`, `COOP`
- `Strict-Transport-Security` при HTTPS
- CORS без wildcard (allowlist хостов)
- `X-Powered-By` отключён

## 2. Техническое состояние и скорость (Core Web Vitals)

### 2.1. Ориентиры CWV
Полевых Lighthouse/CrUX по прод-домену нет (404). Прокси по весу ассетов главной:

| Метрика | Норма | Оценка по коду/весу |
|---------|-------|---------------------|
| LCP | &lt; 2.5 с | **Риск:** hero + lifestyle PNG ~1.8–2.1 МБ × несколько; суммарно ~**8.8 МБ** локальных ассетов на главной |
| INP | &lt; 200 мс | JS умеренный; тяжёлые изображения могут бить по TBT на слабых CPU |
| CLS | &lt; 0.1 | Есть width/height у части img; hero/фоны — следить за резервом места |

**Быстрые wins:** конвертировать `camping.png`, `model-0x.png` в WebP/AVIF &lt; 200–300 KB; `loading="lazy"` ниже fold; preload LCP-изображения.

### 2.2. Индексация
| Файл/тег | Статус |
|----------|--------|
| `robots.txt` | Есть; Disallow `/admin.html`, `/server/`, `/.env` |
| `sitemap.xml` | Главная, 4 продукта, buyers, privacy |
| `canonical` | На главной и product (JS) → `https://northmp.su` |
| Прод | **404** — индексация текущего приложения невозможна, пока DNS/хостинг не укажут на этот стек |
| account/checkout/admin | В sitemap нет (ок); admin закрыт robots |

### 2.3. Ошибки сервера / битые ссылки
Локально публичные HTML/CSS/JS отвечают 200. Критичный «битый» контур — **продакшен-домен**. После фикса чувствительные пути → 404 (ожидаемо).

### 2.4. Адаптивность
Mobile-first в CSS; sticky CTA на карточке товара; меню-бургер с `aria-expanded`. Рекомендуется ручной проход 375 / 768 / 1280 после выкладки.

## Приоритетный backlog

### P0 — до публичного запуска
1. Выкатить приложение на `northmp.su` (сейчас 404 / Tilda imprint).  
2. Убедиться, что на проде нет старых бэкапов `shop-orders.json` в webroot; ротация токенов/паролей, если утечка могла быть на живом стенде.  
3. Боевые ключи ЮKassa + HTTPS + HSTS на edge.

### P1
4. Хеш пароля админа (argon2/bcrypt), ротация session token, опционально HttpOnly cookie + CSRF.

6. Сжать PNG каталога → WebP, цель LCP &lt; 2.5 с.
