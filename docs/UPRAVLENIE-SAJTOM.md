# Инструкция по управлению сайтом Northern Magical Place

Сайт: [https://northmp.su](https://northmp.su)  
Репозиторий: [github.com/samoilovjob-max/NMP](https://github.com/samoilovjob-max/NMP)

Это практическая инструкция для владельца и менеджера: что где менять, как работать с заказами и какие есть ограничения.

---

## 1. Как устроен сайт (коротко)

Сайт состоит из:

| Часть | Что это | Где правится |
|--------|---------|--------------|
| Витрина | Главная, карточки товаров, тексты «О нас», FAQ, контакты | HTML-файлы (`index.html` и др.) |
| Карточки товаров (полная страница) | Название, цена, описание, фото, SEO, FAQ товара | `js/products.js` |
| Серверный каталог | **Реальная цена** при оплате, артикул в заказе и СДЭК | `server/catalog.js` |
| Фото | Файлы картинок | папка `images/` |
| Заказы | Оформление, СДЭК, ЮKassa, личный кабинет | сервер + админка |
| Админка | Только **заказы**, не каталог | `admin.html` |

Важно:

- **Отдельной «админки товаров» нет.** Товары, цены и фото меняются через файлы в проекте (GitHub / Cursor / разработчик) и публикацию на сервер.
- **Цена на сайте и цена в оплате должны совпадать.** Иначе клиент увидит одну сумму, а ЮKassa спишет другую (берётся из `server/catalog.js`).
- Сайт нужно открывать через сервер (`npm start` → `http://localhost:3000`), а не как простой HTML-файл.

## 3. Как менять цену

Нужно изменить цену **в трёх местах** (иначе будет рассинхрон):

### 3.1. Полная карточка товара
Файл: `js/products.js`  
Поле: `price: 18900` (число без пробелов и без «₽»)

### 3.2. Серверный каталог (это цена оплаты!)
Файл: `server/catalog.js`  
То же поле `price` у того же `id`

### 3.3. Главная страница (карточка в блоке «Изделия»)
Файл: `index.html`  
В карточке товара текст вида `от 18 900 ₽` — правится вручную.

После правок: сохранить файлы → закоммитить/залить на сервер → **перезапустить** Node (`npm start`), если сервер уже был запущен.

## 4. Как менять название и описание товара

### Полное описание, заголовок H1, короткий текст, характеристики, сценарии, FAQ, SEO

Файл: **`js/products.js`**

Основные поля одного товара:

| Поле | Зачем |
|------|--------|
| `name` | Короткое имя (корзина, часть интерфейса) |
| `h1` | Большой заголовок на странице товара |
| `badge` | Плашка («Хит сезона», «Дизайн» и т.п.) |
| `short` | Короткий абзац |
| `description` | Полный текст |
| `specs` | Список характеристик |
| `useCases` | Где применять |
| `faq` | Вопросы/ответы на странице товара |
| `seoTitle` | Title вкладки браузера |
| `seoDescription` | Meta description |
| `keywords` | Ключевые слова (чипы + SEO) |
| `imageAlt` / `galleryAlts` | Подписи к фото (важно для SEO) |

### Краткое описание на главной

Файл: **`index.html`**, блок `#catalog` — текст в карточке правится отдельно от `products.js`.

### Название в заказе / админке / СДЭК

Файл: **`server/catalog.js`**, поле `name`.  
Именно оно попадает в заказ и накладную.

## 5. Как менять и добавлять фото товара

### 5.1. Загрузить файл

1. Положите картинку в папку **`images/`**  
   Примеры имён: `product-5.png`, `product-1-detail-2.jpg`
2. Лучше: JPG/PNG/WebP, вес по возможности до ~1–2 МБ, горизонтальные/квадратные кадры без лишнего фона.
3. Можно загрузить через GitHub: *Add file → Upload files* в папку `images/`.

### 5.2. Подключить главное фото

В **`js/products.js`**:

```js
image: "images/product-5.png",
imageAlt: "Понятное описание фото для поиска и слабовидящих",
```

В **`server/catalog.js`** (миниатюра в заказе):

```js
image: "images/product-5.png"
```

На **главной** (`index.html`) — путь в `<img src="...">` карточки каталога.

### 5.3. Дополнительные фото (галерея на странице товара)

В `js/products.js` у товара есть массивы:

```js
gallery: [
  "images/product-1.png",
  "images/main-product.png",
  "images/shore-lake.png"
],
galleryAlts: [
  "Подпись к первому фото",
  "Подпись ко второму",
  "Подпись к третьему"
],
```

- Первое фото в `gallery` обычно совпадает с `image`.
- Клиент на странице товара кликает миниатюры — меняется большое фото.
- Сколько фото нужно — столько строк добавьте в оба массива (длины лучше держать одинаковыми).

Отдельной кнопки «загрузить фото в админке» нет — только файлы + правка `gallery`.

## 6. Как добавить новый товар

Чеклист (нужен доступ к коду/GitHub):

1. **Фото** → загрузить в `images/`
2. **`js/products.js`** → добавить новый объект в массив `NMP_PRODUCTS`:
   - новый `id` (например `"5"`)
   - уникальный `sku` (например `NMP-XX-05`)
   - уникальный `slug` латиницей (`my-new-product`)
   - `price`, тексты, `image`, `gallery`, SEO, FAQ
3. **`server/catalog.js`** → добавить тот же `id`, `sku`, `price`, `name`, `image`  
   Без этого заказ с новым товаром **не создастся**.
4. **`index.html`** → новая карточка в блоке каталога + ссылка `product.html?id=5`
5. **`sitemap.xml`** → добавить URL страницы товара (для поиска)
6. Залить изменения на сервер и перезапустить сайт

Рекомендация по артикулам: формат `NMP-XX-0N`, не менять артикул у уже продававшихся позиций без необходимости.

## 8. Как работает заказ для клиента

1. Клиент выбирает товар → «Оформить» / корзина.
2. На `checkout.html` заполняет ФИО, телефон, e-mail.
3. Выбирает город из подсказки СДЭК.
4. Выбирает **пункт выдачи (ПВЗ)** из списка (карту можно открыть по желанию).
5. Ставит галочку согласия с [политикой конфиденциальности](../privacy.html).
6. Жмёт оплату → создаётся заказ → переход в **ЮKassa**.
7. После оплаты клиент попадает в **личный кабинет** (`account.html`) со статусами:
   - Ожидает оплату  
   - Сборка  
   - Отправка (СДЭК)  
   - Прибыл для получения  
   - Отменён  

Личный кабинет привязан к браузеру (localStorage) + номеру заказа в ссылке. Отдельного логина/пароля нет.

## 9. Админка заказов

### Вход

1. Откройте: `https://northmp.su/admin.html`  
   (локально: `http://localhost:3000/admin.html`)
2. Вставьте токен из файла `.env` на сервере: **`ADMIN_TOKEN`**
3. Нажмите «Войти»

Токен не публикуйте и не коммитьте в Git. Страница админки закрыта от индексации в `robots.txt`.

### Что видно по заказу

- Номер заказа, дата создания / оплаты  
- Состав: товар, **артикул**, количество, сумма  
- Клиент: ФИО, телефон, e-mail  
- Город и адрес ПВЗ  
- Статус оплаты и статус сборки/доставки  
- Срок отгрузки (**Отправить до…**) — по умолчанию 48 часов после оплаты (`SHIP_SLA_HOURS`)  
- Трек СДЭК и этап, если накладная создана  
- Поле заметок менеджера  

Сверху обычно видно счётчики: сколько заказов «к отгрузке» и сколько «просрочено».

### Кнопки и когда их нажимать

| Действие | Когда |
|----------|--------|
| **Сохранить заметку** | Любые комментарии по сборке/звонку |
| **Отметить оплаченным** | Если деньги пришли, а статус не обновился (сбой webhook) |
| **Создать накладную СДЭК** | Оплата есть, а накладная не создалась автоматически |
| **Отметить: сдан в СДЭК** | Физически сдали посылку в СДЭК |
| **Отметить: прибыл в ПВЗ** | Посылка в пункте выдачи / клиент может забирать |

### Типовой процесс менеджера

1. Клиент оплатил → заказ в статусе **Сборка**, появляется дедлайн отгрузки.  
2. Проверить ПВЗ и состав, собрать изделие.  
3. Если нет трека СДЭК — нажать **Создать накладную СДЭК**.  
4. Сдать в СДЭК → **Отметить: сдан в СДЭК**.  
5. Когда прибыло → **Отметить: прибыл в ПВЗ**.  
6. Клиент может сам нажать «Обновить статусы» в личном кабинете (подтянется трек СДЭК).

Админка **не умеет**: менять цены, добавлять товары, загружать фото, делать возврат в ЮKassa, писать e-mail клиенту.

## 10. Оплата (ЮKassa) и доставка (СДЭК)

### ЮKassa

В `.env` на сервере:

```env
YOOKASSA_SHOP_ID=...
YOOKASSA_SECRET_KEY=live_...
PAYMENTS_DEMO=false
PUBLIC_BASE_URL=https://northmp.su
```

В кабинете ЮKassa → HTTP-уведомления:

`https://northmp.su/api/payments/webhook`  

События: `payment.succeeded`, `payment.canceled`.

После успешной оплаты сервер:

1. ставит заказ оплаченным и в статус «Сборка»;  
2. считает срок отгрузки;  
3. пытается создать накладную СДЭК.

Для тестов без реальной оплаты: `PAYMENTS_DEMO=true` (только на тестовом окружении).

### СДЭК

Отправка идёт из настроек:

- город: Петрозаводск (код 450)  
- адрес: Лесной проспект 47  

Габариты посылки для расчёта — общие на все товары (`PACKAGE_WEIGHT/LENGTH/WIDTH/HEIGHT` в `.env`).  
Карта ПВЗ на сайте — OpenStreetMap, без ключа Яндекса.

## 13. Публикация изменений на northmp.su

Обычный цикл:

1. Внести правки в файлы (через GitHub или Cursor).  
2. Залить ветку / смержить в рабочую.  
3. На сервере, где крутится сайт: обновить код и перезапустить `npm start` (или сервис systemd/pm2 — как настроено на хостинге).  
4. Проверить главную, страницу товара, тестовый заказ (в демо) или карточку в админке.

Обязательно для боя:

- `PUBLIC_BASE_URL=https://northmp.su`  
- рабочие ключи ЮKassa и СДЭК  
- webhook ЮKassa  
- сохранённая папка **`server/data/`** (там лежат заказы; если её стереть при деплое — история заказов пропадёт)

## 14. Безопасность

В Git **не должны** попадать:

- `.env`  
- `node_modules/`  
- `server/data/` (заказы)

Если секретные ключи светились в чате или переписке — перевыпустите их в кабинетах СДЭК и ЮKassa и обновите `.env` на сервере.

## 15. Частые вопросы

**Поменял цену на главной, а в оплате старая**  
→ не обновили `server/catalog.js` (и/или не перезапустили сервер).

**Добавил товар на главную, заказ не создаётся**  
→ нет записи в `server/catalog.js` с тем же `id`.

**Фото не видно**  
→ неверный путь (`images/...`), файл не залит на сервер, опечатка в имени (регистр важен).

**Оплата прошла, в админке «не оплачен»**  
→ проверить webhook ЮKassa; временно можно нажать **Отметить оплаченным**.

**Нет трека СДЭК**  
→ **Создать накладную СДЭК** в админке; проверить ключи CDEK и адрес отправителя.

**Клиент не видит заказ в кабинете с другого телефона**  
→ кабинет без логина; откройте ссылку с номером заказа из письма/переписки или найдите заказ в админке.

**Можно ли менять товары только из админки?**  
→ пока нет. Каталог редактируется файлами. Админка — только заказы.
